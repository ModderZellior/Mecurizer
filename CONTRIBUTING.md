## Code Style

- Use 4 spaces for indentation.
- Keep changes scoped and consistent with the existing module layout.
- Prefer edits in `common/`, `fabric/`, and `frapi/` over introducing parallel source trees.

## Pull Requests

- Describe the behavioral change clearly.
- Link any related issue.
- Keep documentation and metadata in sync when changing user-facing behavior.
